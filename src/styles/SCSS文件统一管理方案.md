🎯 SCSS文件统一管理方案

📋 各文件专属内容分工

| 文件名 | 核心存放内容 | 禁止放入的内容 |
| --- | --- | --- |
| `variables.scss` | 全局所有可配置变量：字体栈、字号、色值、间距、圆角、断点等 | 具体样式代码、mixin逻辑 |
| `mixin.scss` | 通用可复用样式片段：字体封装、阴影封装、响应式适配函数等 | 业务专属样式、硬编码数值 |
| `theme.scss` | 多主题适配逻辑：亮色/暗黑模式的CSS变量覆盖、换肤规则 | 具体组件样式、业务页面样式 |
| `element.scss` | ElementUI/ArcoDesign等第三方组件库的全局样式覆盖、主题变量重写 | 自定义业务组件样式 |
| `index.scss` | 按顺序引入所有子样式文件、全局基础重置、根节点基础样式 | 任何业务相关的局部样式 |

🔧 统一管理核心规则
- 导入顺序严格固定：必须按照`variables` → `mixin` → `theme` → `element` → 全局重置的顺序引入，避免出现变量未定义、mixin找不到的编译错误。
- 修改边界明确：任何样式新增时，3秒内就能判断归属文件，比如新增一个全局按钮样式，不能写在index.scss里，应该单独新建`components/_button.scss`引入。
- 避免跨文件依赖：页面专属样式不能修改全局变量，组件样式不能依赖页面专属的类名，保证所有全局样式可以被任意组件安全引用。
- Tauri项目适配：把这套styles目录放在前端代码的src根目录下，和components、pages目录平级，配合Vite的`additionalData`配置，所有单文件组件可以直接读取全局SCSS变量，无需重复导入。

⚠️ 注意事项
- 不要在variables.scss中写业务逻辑相关的变量，所有变量必须是全局通用的基础配置。
- 不要在mixin.scss中写带硬编码色值、字号的片段，所有参数都要从variables中读取，保证全局统一。
- 主题切换时只在theme.scss中覆盖变量，不要重写整套组件样式，避免后续维护成本翻倍。
